# Package reorganization by operator family

Drafted on 2026-09-29 from a read-only audit of `hdgfem/` (import graph,
duplicated helpers, and DR/ADR implementation parity). The audit sections
(Why, DR versus ADR(β = 0) by stage, Correctness items) describe the tree at
that date and use its module paths (`backends/`, `kernels/`, `assembly/`),
which no longer exist. The target layout and implementation status sections
describe the current tree.

## Why

- The subpackages form an import cycle. Imports that point up a layer include:

  | From | To | Import statements |
  |---|---|---:|
  | `core` | `backends` | 20 |
  | `assembly` | `backends` | 23 |
  | `assembly` | `solvers` | 11 |
  | `backends` | `solvers` | 21 |
  | `linalg` | `backends` | 12 |

  Almost all of them are for four kinds of code stored in the wrong place:
  - optional-dependency gates and CuPy mirrors of meshes and spaces
    (`backends/cupy.py`, `backends/advection_cuda.as_cupy_trace_space`);
  - policies and numerical helpers kept in `solvers/` (`stabilization.py`,
    `_diffusion_components`, `_reference_derivative_matrices`, the
    postprocessing cache);
  - linear-algebra code kept in `backends/` (device AMGX solver, host AMGX and
    cupyx solves, `legendre_face_bsr`);
  - logging helpers duplicated in four places.
- `backends/` is flat: 33 modules and about 27.7k lines, named partly by PDE,
  partly by technology and partly by role. `cupy.py` (2.0k lines) is imported
  by 22 sibling modules. `advection_cuda.py` (3.0k lines) holds the AMGX solver
  used by every PDE. `advection_raw_cuda.py` holds the CSR/BSR pattern builder
  shared by DR and ADR.
- The same formulas are implemented many times:
  - the advective face weights τ/γ in at least 8 places;
  - CUDA LU, triangular-solve and orientation routines in about 15 copies,
    generated by three different templating mechanisms;
  - about 10 CuPy local-algebra twins between `advection_cuda.py` and
    `diffusion_cupy.py`.

  Several copies have already diverged; see [Correctness items](#correctness-items).

## Organizing principle

The package has two HDG discretization families rather than three PDEs.

- **Transport (first-order) HDG**: advection-reaction (AR). There is no flux
  unknown, and the face weights come from upwind τ/γ.
- **Mixed (second-order) HDG**: diffusion-reaction (DR) and
  advection-diffusion-reaction (ADR).
  - Both have unknowns `[u, qx, qy]` with `q = -κ∇u`, the same local block
    layout and signs, and τ in the same three places (element-boundary
    u-row, lift, interior trace mass).
  - DR is ADR with β = 0 whenever τ_adv(β = 0) = 0. This holds for the whole
    upwind family (`None`, `ScaledUpwind`, `"lax-friedrichs"`) but not for an
    explicit scalar or field τ_adv.

Organize by family, then by stage (coefficients → local operator →
condensation/assembly → reconstruction → postprocessing), then by backend.
Every backend of one stage sits in the same subpackage so that parity gaps are
visible.

### Layering rule

```
runtime → core → cases → linalg → hdg → {transport, mixed} → solvers → diagnostics → io
```

A module imports only from its own layer or from layers to its left;
function-level imports count. `transport` and `mixed` never import each other.
The package root is the public facade over every layer.
`tests/test_package_layering.py` enforces the rule with an empty
allowed-violation list.

## Target layout (as implemented)

The tree below is the final layout. It differs from the 2026-09-29 draft in
these points:

- `projection` lives in `core/`, next to the generic mass matrices and the
  CuPy mirrors, not in `hdg/`;
- device sparse views and scaling kernels live in `linalg/gpu/sparse`, not in
  `hdg/cuda/`;
- advection τ/γ policies are in `hdg/stabilization`; diffusion τ policies are
  in `mixed/stabilization`;
- transport failure diagnostics live in `transport/diagnostics`, and
  `diagnostics/` holds `errors`, `solver` and `guiding_center`;
- DR and ADR modules sit side by side in `mixed/` (`numba`/`adr_numba`,
  `local_numpy`/`adr_numpy`) and share building blocks instead of forming one
  kernel family; postprocessing is split into DR (`flux`) and ADR
  (`total_flux`) drivers over shared kernels;
- the ADR raw-CUDA pipeline is `solvers/advection_diffusion_reaction_device`,
  over the operator API in `mixed/raw_cuda/adr_operator`.

## Implementation status (2026-10-01)

Phases 0–5 and 7 are done on branch `package-reorganization`. The layering
test passes with zero allowed violations; `hdgfem/backends/`,
`hdgfem/kernels/` and `hdgfem/assembly/` are removed without compatibility
shims, as are the DR primal-postprocess CuPy and raw-CUDA ports and the
unreachable generic Numba DR adapters. The public names in `hdgfem` and
`hdgfem.solvers` are unchanged. The Bernstein postprocess branches are kept:
flux recovery supports Bernstein traces and is reachable from the
guiding-center runner. Splitting the large solver modules into per-backend
drivers is a recorded follow-up in `TODO.md`.

Phase 6 is done as shared building blocks rather than one merged kernel
family: 6.1 flux postprocessing (`mixed/postprocess/numba_kernels`), 6.2 the
NumPy local inverse and assembler (`mixed/local_numpy`), and 6.3 the Numba
condensation and column solve (`mixed/numba_common`). Replacing the DR kernels
wholesale by the ADR kernels would lose DR's projected tables and cached
Schur factors, which are its fast path. For raw CUDA (6.4), AR, DR and ADR
share the cooperative LU source `hdg/cuda/raw_source.RAW_COOP_LU_FACTOR`.

Correctness items A1, A2 and A5 are fixed; A3 remains a watch item.

A4 is fixed, scoped to non-finite values as decided. Non-finite local
reconstruction results raise `LinAlgError` through
`hdg/condensation_device.require_finite_device_values`. The AMGX path already
rejects non-finite systems, and tiny-pivot clamping is unchanged.

## DR versus ADR(β = 0) by stage

| Stage | Same math? | Current state |
|---|---|---|
| Local system and static condensation | yes | NumPy ADR already imports DR's lift/boundary helpers. Numba has near-duplicate kernel pairs (`_build_projected_diffusion_operator` / `_build_local_operator`). CuPy has no ADR assembly. Raw CUDA has separate DR and ADR kernel families. |
| RT flux recovery | yes, for face-constant τ | Already one implementation on host, Numba and CuPy (`_postprocess_rt_flux_from_samples`). The raw-CUDA copy is DR-named but contains nothing DR-specific. |
| L2-closest flux recovery | yes | Two Numba kernels. The DR kernel computes face gaps inside the kernel; the ADR kernel takes them precomputed on the host. |
| Primal p+1 postprocess | **no** | DR solves a Stenberg-type problem on q_h with cached, κ-independent factors. ADR solves a local mixed problem on the recovered flux. Both methods stay. |

### DR fast paths to keep as specializations

- SPD Cholesky when β = 0 and τ > 0: the scalar Schur block
  `M_τ + DᵀM⁻¹D` is SPD. ADR currently always uses LU.
- Identity κ (no κ⁻¹ mass).
- Scalar τ passed as a kernel argument.
- Local blocks computed on the fly rather than as dense per-element tables.
- RHS-only reuse. Raw-CUDA ADR reassembles on every solve.
- The compact warp kernels in `diffusion_cupy`.
- The fb-hp-mg-pcg BSR integration.

### Merges that change numbers

- DR Numba projects κ⁻¹ into P_p; ADR samples κ⁻¹ exactly (kinds 0–6).
- DR uses exact reaction triple products; ADR samples the reaction at
  quadrature points.

Merging either one changes DR results for variable κ or reaction. This needs an
explicit decision (see [Open decisions](#open-decisions)).

## Correctness items

These came to light because copies of the same routine have diverged. Fix each
one in its own commit, with a regression test, before any code moves, so that
the reorganization itself stays behavior-preserving.

| # | Issue | Status |
|---|---|---|
| A1 | `backends/cupy.py` `diagonal_scale_csr_rows` guards only a zero diagonal. The `advection_cuda.py` kernel of the same name also falls back to the row maximum for tiny or non-finite diagonals. The weak copy is used by the AR cupyx handoff (`linalg/cupyx_device.py`). The sibling `csr_inverse_sqrt_diagonal`, used by AMGX symmetric scaling, has the same weak guard. | fixed 2026-09-30 (`tests/test_cupy_scaling.py`) |
| A2 | `solvers/advection_diffusion_reaction._adr_postprocess_samples` handles τ_adv itself. `"lax-friedrichs"` reaches `float("lax-friedrichs")`, and `ScaledUpwind` falls through to the array branch, although ADR assembly accepts both through `matrices_numpy.advection_trace_stabilization_values`. | fixed 2026-09-30 (`tests/test_adr_face_stabilization.py`) |
| A3 | ADR computes γ = τ_total − β·n from the raw β·n (`assembly/advection_diffusion_reaction.py`, `backends/adr_coefficients_cupy.py`). AR uses `effective_advection_normal_flux` and the inactive-face gauge. `conflict-averaged-upwind` is likely inconsistent in ADR, and it is not rejected. | watch item (open decision 3) |
| A4 | The AR/DR CUDA LU copies clamp tiny pivots to ±1e-30, and `fabs(d) < 1e-30` is false for NaN, so NaN spreads silently. The ADR warp LU, ADR serial LU and RT postprocess return a failure status instead. | fixed 2026-10-01: non-finite reconstruction outputs raise `LinAlgError` |

## Phases

The work runs in a separate worktree on branch `package-reorganization`,
created once the concurrent uncommitted work is committed. `TODO.md` holds the
execution protocol: per-phase gates, the phase 6 performance gate, and the
final merge procedure.

Each phase is its own commit or commit series. In every phase, the imports in
`hdgfem/`, `tests/` and `scripts/` are updated by codemod, CODEMAP rows are
updated in the same change, and the affected tests are run.

0. **Safety net.** Start from a committed working tree.
   - Add a layering test that records the current upward imports as a baseline
     and fails on any new ones.
   - Add DR versus ADR(β = 0) parity tests for local blocks, reduced systems,
     RT and l2_closest flux recovery. None exist today.
1. **Correctness items A1–A5**, each with a regression test.
2. **Break the cycles.** Create `runtime/` (gates, precision, logging, error
   types) and `core/device.py` (mirrors, mesh maps, orientation mode). The
   `core → backends` imports disappear.
3. **Build `hdg/`.**
   - One stabilization evaluator, coefficient sampling, reference tables.
   - The CUDA library (`raw_source`, `launch`, `pattern`, `sparse`).
   - Where copies diverged, the better-behaved copy wins.
   - The `assembly → solvers` and `backends → solvers` imports disappear.
4. **Consolidate `linalg/`.**
   - Create `amgx/` (the device solver moves out of `advection_cuda.py`),
     `gpu/`, `multigrid/` and `reduction`.
   - Split `system.py` and move `FaceDenseSystem` into `linalg`.
   - The `linalg → backends` imports disappear.
5. **Move files into `transport/` and `mixed/` without changing behavior.**
   Numba `cache=True` caches are rebuilt once.
6. **Merge inside `mixed/`, from lowest to highest risk, each step gated by the
   phase 0 parity tests:**
   1. flux postprocessing (one sampler; merged l2 kernel with a small Numba
      diffusion-gap kernel to keep DR's fast path);
   2. NumPy local solver and assembler (ADR gains penalty mode and the
      identity-κ closed form);
   3. the Numba kernel family (`has_advection`, `factor_kind`, cached factors,
      RHS-only kernel, on-the-fly boundary blocks);
   4. raw CUDA last, once ADR has a β = 0 Cholesky variant and RHS-only reuse.
7. **Tidy up.**
   - Create `diagnostics/` and `cases/`, and split
     `solvers/diffusion_reaction.py` into options, solver and device modules.
   - Resolve the dead and test-only code (see [Open decisions](#open-decisions)).

## Open decisions

Decided on 2026-09-29:

1. **Old import paths:** clean break. Every in-repo import is rewritten by
   codemod, and no re-export shims are kept.
2. **Bit-compatibility:** not required. Merged DR paths use ADR's sampled κ⁻¹
   and reaction. Changed DR results for variable κ or reaction must come with
   convergence checks and documented tolerances.
3. **Conflict-averaged upwinding in ADR:** keep ADR's current semantics (γ from
   the raw β·n, no inactive-face gauge). Diffusion (τ_diff > 0) is expected to
   keep the trace rows full rank. The shared evaluator exposes this as an
   explicit ADR mode, and A3 stays open as a watch item.
4. **Dead and test-only code:** delete it, together with tests that only cover
   it:
   - the DR primal CuPy and raw-CUDA ports;
   - the Bernstein postprocess branches (kept after review; see Implementation
     status);
   - `backends/numpy.py`;
   - the unreachable Numba DR generic branches.

   The legacy aliases `adv_rea`/`diff_rea` follow the existing TODO item on
   removing compatibility shims.
5. **Package name:** the shared layer is `hdgfem/hdg/`.
6. **Scope:** all phases, including the phase 6 kernel merges.
